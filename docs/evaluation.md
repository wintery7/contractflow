# 검색·답변 품질 평가

> 평가 코드: [`evaluation/`](../evaluation/) · 원본 결과: [`evaluation/results/`](../evaluation/results/)
> 이 문서에는 **실제로 실행한 결과만** 기록한다.

## 1. 평가 데이터

| 항목 | 내용 |
|---|---|
| 계약서 | 가상 계약서 4건 (용역·물품공급·업무위탁·비밀유지), 각 3페이지 — [contracts.py](../evaluation/datasets/contracts.py) |
| 질문 | 40개 — [questions.jsonl](../evaluation/datasets/questions.jsonl) |
| 유형 | 사실 15 · 조항 위치 4 · 여러 문장에 걸친 조건 6 · 비슷하지만 다른 조항 4 · 문서에 없는 정보 8 · 모호 3 |
| 정답 근거 | 원문 구절을 그대로 기록. 데이터셋 검증 테스트가 모든 구절이 원문에 있는지 확인한다 |

계약서는 서로 비슷하지만 다른 조항(해지/해제, 지체상금/손해배상/위약벌, 수수료 감액/손해배상 한도)을 일부러 섞어 구별 능력을 보도록 만들었다. 실제 계약서가 아니라 직접 작성한 데이터이므로 **실제 업무 문서에서의 성능을 대표하지 않는다.**

## 2. 지표

| 지표 | 정의 |
|---|---|
| 관련 청크 | 정답 근거 구절 중 하나라도 (공백 무시) 그대로 포함한 청크 |
| Recall@k | 상위 k개 안에 관련 청크가 하나라도 있는 질문의 비율 |
| Evidence coverage@k | 질문의 정답 근거 구절 중 상위 k개에 들어 있는 비율의 평균 (여러 조건을 모두 찾았는지) |
| MRR@10 | 첫 관련 청크 순위의 역수 평균 (10위 밖이면 0) |
| 임계값 통과율 / 차단율 | 최고 유사도 기준 — 답할 수 있는 질문이 통과하는 비율 / 문서에 없는 질문이 걸러지는 비율 |
| 답변률, 인용 적중률 | 답할 수 있는 질문에 답한 비율 / 인용한 청크에 정답 근거가 있는 비율 |
| 키워드 일치율 | 정답 핵심 표현이 답에 모두 들어 있는 비율 (표기가 다른 정답도 틀림으로 세는 엄격한 기준) |
| 거절률 | 문서에 없는 질문에 답하지 않은 비율 |
| 근거 없는 주장 발생률 | (문서에 없는 질문에 답한 수 + 정답 근거를 인용하지 못한 답 수) / 전체 답변 수 |
| 지연 | 질문 임베딩 + 검색 + 답변 생성 (평균, p50, p95) |

검색 점수(유사도)와 답변의 근거 일치는 별개로 측정한다. 유사도가 높아도 비슷한 다른 조항일 수 있기 때문이다.

## 3. 실험 절차

한 번에 한 변수만 바꾸고, 앞 단계에서 고른 값을 다음 단계의 고정값으로 쓴다.

1. **E1 청크 크기** 300 / 500 / 800 / 1200자 (겹침 100, 벡터 검색)
2. **E2 겹침** 0 / 50 / 100 / 200자 (E1에서 고른 크기)
3. **E3 top-k** 1 / 3 / 5 / 8
4. **E4 검색 방식** 벡터 / BM25(글자 2-gram) / 하이브리드(RRF)
5. **근거 부족 임계값** 0.15 ~ 0.60
6. **답변 평가** 고른 설정으로 40문항 전체를 실제 LLM으로 실행

선택 규칙: Recall@3 최대 → MRR@10 최대 → 더 작은 값(비용이 적은 쪽).

```bash
uv run python -m evaluation.run_retrieval_eval          # 1~5
uv run python -m evaluation.run_answer_eval --max-chars <E1> --overlap <E2> --top-k <E3> --min-score <임계값>
```

### 4.1 검색 (질문 40개 중 정답 근거가 있는 32개)

**E1 청크 크기** (겹침 100, 벡터)

| max_chars | Recall@1 | Recall@3 | Recall@5 | MRR@10 | 문서당 청크 수 |
|---|---|---|---|---|---|
| 300 | 0.781 | 0.969 | 1.0 | **0.872** | 10.0 |
| 500 | 0.719 | 0.969 | 1.0 | 0.836 | 7.8 |
| **800** | 0.750 | **1.0** | 1.0 | 0.865 | 4.2 |
| 1200 | 0.719 | 1.0 | 1.0 | 0.854 | 3.0 |

→ **800** 선택 (Recall@3 최대 중 MRR이 높은 쪽). 300은 MRR이 가장 높지만 Recall@3에서 1문항을 놓쳤다.

**E2 겹침** (800자, 벡터)

| overlap | Recall@1 | Recall@3 | MRR@10 | 문서당 청크 수 |
|---|---|---|---|---|
| 0 | 0.656 | 1.0 | 0.802 | 3.2 |
| 50 | 0.688 | 0.969 | 0.820 | 4.0 |
| **100** | 0.750 | **1.0** | 0.865 | 4.2 |
| 200 | **0.875** | 0.938 | **0.914** | 5.5 |

→ **100** 선택. 겹침 200은 1위 적중률이 크게 오르지만(0.75 → 0.875) 3위 안에서 놓치는 문항이 생겼다.
겹침이 늘수록 거의 같은 내용의 청크가 상위를 나눠 가져 다른 관련 청크가 밀려나는 것으로 보인다.

**E3 top-k** (800/100, 벡터): Recall@1 0.75 → **Recall@3 1.0** → @5·@8 1.0. Evidence coverage도 같다. → **k=3**

**E4 검색 방식** (800/100)

| method | Recall@1 | Recall@3 | MRR@10 |
|---|---|---|---|
| 벡터 | 0.750 | 1.0 | 0.865 |
| BM25 (글자 2-gram) | 0.875 | 1.0 | 0.927 |
| 하이브리드 (RRF) | 0.875 | 1.0 | **0.938** |

Recall@3은 셋 다 1.0이라 선택 규칙상 차이가 없다. 다만 **1위 적중률은 키워드 검색이 섞일 때 0.75 → 0.875로 올랐다.**
"지체상금", "위약벌"처럼 조항 이름이 질문에 그대로 나오는 계약서 특성 때문으로 보인다. 서비스는 벡터 검색을 유지하고
(top-3을 모두 LLM에 넘기므로 Recall@3이 같으면 답변 품질 차이가 작다), 하이브리드는 다음 개선 후보로 둔다.

**근거 부족 임계값** (벡터 1위 유사도)

| threshold | 답할 수 있는 질문 통과율 | 문서에 없는 질문 차단율 |
|---|---|---|
| 0.15 ~ 0.25 | 1.0 | 0.125 |
| 0.30 | 0.931 | 0.125 |
| 0.35 | 0.759 | 0.375 |
| 0.40 | 0.483 | 0.875 |
| 0.45 이상 | 0.379 이하 | 1.0 |

**유사도만으로는 "문서에 없는 질문"을 가려낼 수 없었다.** 문서에 없는 질문의 대부분을 막으려면(0.40) 답할 수 있는 질문의
절반을 버려야 한다. "준거법은?"처럼 문서에 없는 질문도 계약서 문장과 주제가 비슷해 유사도가 높게 나오기 때문이다.
그래서 임계값은 기본값 0.25(정상 질문을 하나도 막지 않음)로 두고, 거절은 2단계인 LLM 판단에 맡긴다. 아래 답변 평가가 그 결과다.

### 4.2 답변 (800자 / 겹침 100 / top-3 / 임계값 0.25 / 벡터, 질문 40개 전체)

| 구분 | 지표 | 결과 |
|---|---|---|
| 답할 수 있는 질문 (29) | 답변률 | **100%** (29/29) |
| | 인용 적중률 (인용 청크에 정답 근거 포함) | **100%** |
| | 키워드 일치율 (엄격) | **100%** |
| 문서에 없는 질문 (8) | 거절률 | **87.5%** (7/8) — 임계값 차단 1, 모델 거절 6 |
| 전체 답변 (30) | 근거 없는 주장 발생률 | **3.3%** (1/30) |
| 지연 (임베딩 + 검색 + 답변) | 평균 / p50 / p95 / 최대 | 5.9s / 5.5s / **10.6s** / 13.1s |
| 비용 | 토큰 (40문항 합계) | 입력 41,884 / 출력 14,833 |
| 오류 | API 오류율 | 0% |

**2단계 근거 판단이 실제로 어떻게 나뉘었나**: 문서에 없는 질문 8개 중 유사도 임계값이 막은 것은 1개뿐이고, 6개는 LLM이
"발췌문에 근거 없음"으로 거절했다. 4.1의 임계값 분석과 일치한다. 임계값은 명백히 무관한 질문의 LLM 호출 비용을 줄이는 역할이고,
실질적인 환각 방지는 "거절 허용 + 실제 발췌문 인용 강제"가 맡는다.

**근거 없는 주장 1건의 실제 내용**: q39 "계약기간이 끝나면 자동으로 갱신되나요?"(자동 갱신 조항이 없는 계약)에
모델은 "발췌문에는 자동갱신 규정이 없습니다. 제5조에 '본 계약의 기간은 체결일부터 2년간으로 한다.'만 규정되어 있습니다"라고 답했다.
**내용은 맞는 답**이지만, 지표는 "문서에 없는 질문에 답하면 근거 없는 주장"으로 정의되어 있어 실패로 셌다.
"없다"는 답을 거절로 볼지 정답으로 볼지는 서비스 정책의 문제라 지표 정의는 바꾸지 않았다.

**모호한 질문 3개** (정확도 집계 제외): 1개는 모델이 거절, 2개는 답변.

### 4.3 이 결과로 바꾸지 않은 것

- 서비스 기본값(`CHUNK_MAX_CHARS=500`, `QA_TOP_K=5`)은 그대로 두었다. 800자 / top-3이 이 평가셋에서 더 나았지만,
  청크 설정을 바꾸면 기존 문서 전부를 다시 색인해야 하고, 데이터가 40문항이라 한두 문항 차이로 순위가 뒤집힌다.
  실제 문서로 평가셋을 늘린 뒤 바꾸는 것이 맞다고 판단했다.
- 재정렬(reranking)은 넣지 않았다. top-3 안에 정답 근거가 100% 들어왔으므로 현재 데이터에서는 이득이 확인되지 않는다.

(평가 코드·데이터·지표 계산 자체는 단위 테스트로 검증되어 있다 — `tests/unit/test_evaluation.py`)

## 5. 해석 시 주의

- 질문 40개, 계약서 4건이라 수치의 분산이 크다. 한두 문항 차이로 비율이 2.5~5%p씩 움직인다.
- 정답 근거 판정은 "구절이 청크에 그대로 들어 있는가"이므로, 겹침이 없을 때 구절이 청크 경계에서 잘리면 관련 청크로 세지 않는다. 이것은 겹침의 효과를 보여 주는 의도된 기준이다.
- 키워드 일치율은 "300만 원"처럼 표기만 다른 정답도 틀림으로 센다.
- LLM 답변은 실행마다 달라질 수 있다. 4.2는 **1회 실행** 결과다.
- 서비스 기본 모델(`gpt-5.4-mini`)이 아니라 `gpt-5-mini`로 측정했다. 모델에 따라 거절 성향이 다르다
  (같은 날 프롬프트 인젝션 live 테스트에서 `gpt-5-mini`는 4회 중 1회 문서 속 지시를 따랐다 — [07 M2 기록](design/07-m2-analysis-notes.md#3-프롬프트-인젝션-방어)).
