# 주요 오류와 개선 사례

개발 중 실제로 발생한 문제와 원인, 해결 방법을 기록한다. 모두 이 저장소의 커밋으로 확인할 수 있다.

## 1. 업로드 크기 제한이 본문을 다 받은 뒤에야 동작함

| | |
|---|---|
| 증상 | 크기 초과 파일을 413으로 거절하도록 FastAPI 의존성(`Depends`)에 검사를 넣었지만, 거절 시점에 이미 20MB 본문을 전부 수신했다 |
| 원인 | FastAPI는 엔드포인트 의존성을 실행하기 **전에** multipart 본문을 파싱한다 |
| 해결 | 검사를 미들웨어로 옮겨 `Content-Length`가 한도를 넘으면 본문을 읽기 전에 413을 반환. 헤더 없는 chunked 요청을 위해 서비스에서 실제 바이트 수를 한 번 더 검사(다층 방어) |
| 검증 | 미들웨어만 반환하는 `details.max_body_bytes` 키로 "서비스가 아니라 미들웨어가 거절했다"를 구분하는 테스트 |

## 2. 같은 트랜잭션에서 만든 행의 생성 시각이 모두 같음

| | |
|---|---|
| 증상 | "최신순 목록", "가장 최근 분석" 테스트가 간헐적으로 실패 |
| 원인 | PostgreSQL `now()`는 **트랜잭션 시작 시각**을 반환한다. 테스트는 바깥 트랜잭션 하나 안에서 실행되므로 모든 행의 `created_at`이 같았고, 동점은 무작위 UUID 순서로 정렬됐다 |
| 해결 | 문서 목록은 운영에서 요청마다 트랜잭션이 분리되므로 테스트에서 시각을 명시. 반면 "최신 분석"은 비즈니스 규칙이므로 분석·업무 테이블은 실제 삽입 시각인 `clock_timestamp()`로 변경 |

## 3. 테스트에서 세션 하나를 공유해 캐시 문제를 가림

| | |
|---|---|
| 증상 | 백그라운드 실행기가 DB를 바꾼 뒤 API가 오래된 값을 읽을 위험이 테스트에서 드러나지 않음 |
| 원인 | 모든 요청이 테스트용 세션 하나를 공유해 SQLAlchemy identity map(1차 캐시)이 공유됨 |
| 해결 | 테스트에서도 운영처럼 요청·실행기마다 새 세션을 열고, 같은 커넥션의 SAVEPOINT로 격리 (`join_transaction_mode="create_savepoint"`) |

## 4. 통합 테스트가 다른 프로젝트 DB를 지울 수 있었음

| | |
|---|---|
| 상황 | 기존 PostgreSQL에 다른 프로젝트 DB(`ai_workflow`)가 있었고, 통합 테스트는 시작 시 스키마를 `downgrade base`로 지운다 |
| 해결 | 테스트 DB를 `DATABASE_URL`의 DB 이름 + `_test`로 자동 도출하고, 이름이 `_test`로 끝나지 않으면 **연결 전에 실행을 거부**하는 안전장치 추가 (테스트로 확인) |

## 5. 개발 PC의 PostgreSQL에 pgvector가 없음

| | |
|---|---|
| 상황 | Windows용 pgvector는 관리자 권한과 Visual Studio 빌드 도구로 직접 빌드해야 하고, Docker Desktop은 WSL 미설치로 사용할 수 없었다 |
| 해결 | 개발·테스트는 pgvector가 포함된 PostgreSQL 16 바이너리(`pgserver` 개발 의존성)를 5433 포트로 띄우는 스크립트 사용, CI와 배포는 공식 이미지 `pgvector/pgvector:pg16`. 접속 정보는 `DATABASE_URL` 하나로만 바뀌므로 코드 변경 없음 |

## 6. 한국어 Windows 환경 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| `alembic.ini` 읽기 실패 (`UnicodeDecodeError: cp949`) | Alembic이 설정 파일을 시스템 로캘 인코딩으로 읽음 | 설정 파일은 ASCII만 사용 |
| curl로 올린 한글 파일명이 깨짐 | Windows 터미널이 인자를 cp949로 전달 (서버 문제 아님) | Python 클라이언트로 UTF-8 파일명을 보내 서버 동작이 정상임을 확인 |
| `uv init`이 Python 3.14로 가상환경 생성 | 버전 고정 파일이 없었음 | `.python-version`으로 3.11.9 고정. 3.12 문법(`class Page[T]`)도 `TypeVar`로 교체 |

## 7. `pg_ctl start`를 실행한 명령이 끝나지 않음

로컬 DB 스크립트가 `pg_ctl`을 실행하면 서버 프로세스가 부모의 출력 파이프를 물려받아 호출자가 영원히 대기했다. `pg_ctl`은 출력을 `DEVNULL`로 연결하고 서버 로그는 `-l` 파일로 남기도록 수정했다.

## 8. 비밀값이 원격 저장소에 올라갈 뻔함

`.env.example`에 실제 비밀번호가 입력된 상태로 커밋 대상이 되었다. 아직 push 전이었으므로 해당 파일을 **커밋 기록에서 제거**(filter-branch)하고 `.gitignore`에 추가했으며, push 전에 모든 커밋을 대상으로 키 패턴과 `.env` 계열 파일을 검사하는 절차를 두었다. 환경변수 목록은 README 표로 문서화했다.

## 9. 검사가 실패했는데 커밋됨 (작업 절차 오류)

테스트 결과를 `grep "passed"`로 판정했더니 `58 passed, 24 errors`도 통과로 처리되어 커밋이 만들어졌다. 이후 모든 커밋은 pytest·ruff의 **종료 코드**로 판정한다. CI에서도 같은 검사를 자동으로 실행한다.

## 10. Fake 임베딩에 기대는 테스트가 불안정

테스트용 Fake 임베딩(글자 2-gram 해시)은 글자가 겹치는 정도만 반영한다. "계약기간"이라는 단어가 비밀유지 조항("계약기간 중은 물론…")에도 있어 기대와 다른 청크가 1위가 됐다. 검색 **품질**은 실제 임베딩으로 평가 하네스에서 측정하고, 단위·통합 테스트는 결정적으로 보장되는 성질(순서 정렬, 인용 검증, 근거 부족 처리)만 확인하도록 질문을 바꿨다.

## 11. 외부 LLM API 키 실효 (401)

진행 중 OpenAI API 키가 401로 거부되기 시작했다. 앱은 이를 `LLM_REQUEST_REJECTED`(분석 실패) / `503`(질의응답)으로 변환해 처리했고, 원인을 좁히기 위해 `.env` 수정 전후의 키를 **값 대신 해시로 비교**해 설정 변경이 원인이 아님을 확인했다. 로그 포매터는 `sk-` 패턴을 마스킹한다.
