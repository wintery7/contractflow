> 기록된 뒤에만 추가한다. (2026-11-09 기준 평가 미실행)

## 한 줄 소개

**ContractFlow AI** — 계약서 PDF에서 핵심 조건을 근거 인용과 함께 추출하고, RAG 질의응답과 검토 업무 관리를 제공하는 AI 백엔드 (개인 프로젝트, 2026.10 ~ 2026.11)

**기술**: Python 3.11, FastAPI, Pydantic, SQLAlchemy 2, Alembic, PostgreSQL + pgvector, OpenAI API, PyMuPDF, pytest, Docker, GitHub Actions

## 주요 내용 (이력서 bullet 후보)

- **근거 검증 구조화 추출**: 10개 계약 항목을 필드별 상태(FOUND/NOT_FOUND/AMBIGUOUS)·원문 인용·페이지로 추출하고, 서버가 인용문을 원문 페이지와 대조해 검증 상태를 표시. 상태와 값이 모순되는 응답(환각 패턴)은 스키마 검증으로 거절하고 1회 교정 재시도
- **근거 기반 RAG 질의응답**: 조항 경계 청킹(페이지 범위 보존), pgvector 문서 범위 정확 검색, 유사도 임계값 미만 시 LLM 미호출, 실제 검색 청크를 인용하지 않은 답은 반환하지 않는 2단계 근거 판단
- **비동기 분석 파이프라인**: 202 응답 후 백그라운드 실행, 단계별 상태 기록, 부분 유니크 인덱스·행 잠금·멱등 실행기로 중복 분석 방지, 재시작 시 중단 작업 정리
- **업무 관리**: AI 제안은 사용자 승인으로만 업무화(중복 승인 DB 제약), 상태 전이 규칙, version 기반 낙관적 잠금, 필드 단위 변경 이력
- **품질·운영**: 단위·통합 테스트 236개(실제 PostgreSQL, 트랜잭션 롤백 격리, Fake LLM으로 장애 시나리오 재현), 질문 40개 검색·답변 평가 하네스(Recall@k·MRR·근거 없는 주장 발생률·지연 p95), Docker 2단계 빌드, CI 워크플로, 민감정보 미기록 JSON 로그

## 면접에서 꺼낼 개선 사례 (상세: `troubleshooting.md`)

- FastAPI 의존성은 multipart 본문 수신 후 실행됨을 발견해 크기 제한을 미들웨어로 이동
- PostgreSQL `now()`(트랜잭션 시작 시각)로 인한 정렬 불안정을 발견해 `clock_timestamp()` 적용
- 통합 테스트가 다른 DB를 지우지 않도록 `_test` DB가 아니면 실행을 거부하는 안전장치 추가
